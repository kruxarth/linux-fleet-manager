Linux Fleet Manager

Manage many Linux machines.
Know when they break.

A control plane that onboards nodes, tracks whether they're alive, runs a short list of safe commands on them, and shows system metrics in Grafana.

Space = play/pause · ← → = step · click the bar to seek

1 · The problem

What the assignment asks for

OnboardingAdd VMs or bare-metal nodes under central management.
AvailabilityDetect when a node dies, and keep working for the rest (graceful degradation).
Controlled executionRun commands remotely without giving everyone a root shell.
ObservabilityCollect, store and visualise CPU / RAM / disk / network with Prometheus + Grafana.

Graded on correctness, system design, observability and Linux internals, not looks.

2 · The solution

One manager, a small agent per node, two separate signals

The manager never connects into nodes. Agents call out, so NAT'd and firewalled machines work.

4 · Availability

Node lifecycle: state is derived from the last heartbeat

pending → heartbeat → online → heartbeat stops for 90s → offline → heartbeat resumes → online

A failed command marks the node degraded: still reachable, but flagged. An admin delete makes it revoked, and its token is rejected from then on.

Computed, not just storedEffective() recomputes the state from timestamps on every read, so the UI is right even between reaper ticks.
Graceful degradationOffline nodes refuse new commands; list and detail pages and the other nodes keep working.
5 · Onboarding

From nothing to a managed node

1. Admin clicks Onboard → manager creates a short-lived, single-use enrollment token (stored hashed).
2. On the node: curl …/install.sh?token=… | sudo bash installs the agent as a systemd service.
3. Agent POSTs inventory (hostname, kernel, arch) with the token → manager consumes it atomically and mints a long-lived node token.
4. Agent saves the node token (mode 0600) and starts heartbeating every 15s. Identity is a UUID, not the hostname.
Replay? A second enroll with the same token gets 401.
6 · Controlled execution

An allowlist, enforced twice

- id: disk
  argv: ["df", "-h"]
  timeout_seconds: 10
Manager sideThe operator picks an id, never raw text. Unknown ids → 400. Node not online → 409. Every request is audit-logged.
Agent side (new)The agent re-checks that id and argv match its own local catalog. A compromised manager can't push arbitrary programs.
ExecutorNo shell, fixed env, timeout, kills the whole process group, output capped at 1 MiB.
Pull modelAgent long-polls for jobs, runs one at a time, then posts the result.
7 · Observability

Two independent signals on purpose

Liveness: heartbeat → SQLiteAnswers: is the control channel up? May we send commands?
Health: node_exporter → Prometheus → GrafanaAnswers: what is the machine doing right now?

If the agent dies but the exporter lives, Grafana still shows data while the manager says offline. If scrapes fail but heartbeats work, the node stays online. One plane failing doesn't hide the other.

The manager also exposes /metrics: fleet_nodes{state}, command counters and duration, enrollments, heartbeats. Prometheus discovers node targets through /api/v1/prometheus/sd.

8 · Demo

How to run it

export FLEET_ADMIN_TOKEN=dev-admin-token
make web && make run-server        # UI at http://localhost:8080
# UI → Onboard → copy the token, then in another terminal:
export FLEET_MANAGER_URL=http://127.0.0.1:8080
export FLEET_ENROLL_TOKEN=<token>
make run-agent
Node appears online → open it → run uname / disk → see output.
Stop the agent → within ~90s it flips to offline and commands are refused (409).
Revoke it in the UI → the agent exits instead of retrying forever.
Full stack: docker compose -f deploy/docker-compose.yml up --build → Prometheus :9090, Grafana :3000.
